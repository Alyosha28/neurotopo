# Gate 1 候选因素资格：下一正式效果前的执行清单

此模板来自 STR-0003 任务后反思，**不是任何候选的注册协议或自动批准**。下一具名候选在进入项目 `QUESTION` **之前**须有版本化的K因素/claim-track资格裁定与独立先例/科学审查；至少在**首次控制资格数据之前**冻结所有§26操作统计量、阈值/不确定区间及后果，不能用资格数据反调。`ResearchLoop.begin` 的结构JSON通过仍只到QUESTION；失败的固定任务/模型配置关闭，任何新版本需独立问题和全部尝试记录。

**STR-0004/决定0043前瞻补充：**同容量强单流GRU可以用块对角权重精确实现K条独立GRU，故“强单流功能上绝不能有内部分槽”不是有效准入要求；若训练后出现分槽，报告它而不事后取消对照。仅换mask仍不能**自动**称K因素；若具名操作明确为显式独立递归组织，并且多块持续/活跃/非冗余护栏通过，可前瞻检验这一**架构组织与连接分配**的受限Gate1收益，同时必须胜匹配稀疏和强稠密保护。正效不证明纯K数、假设语义、单流表达不可能或新颖性。决定0043不重开G1-RS v0/旧EXP，任何新版本仍需独立科学审查与数值协议。现行`gate1_candidate_first_v1`结构入口已允许`h3_candidate`进入QUESTION，结构放行不等于决定0043的科学资格；`reference_k`仍被项目入口拒绝。

**STR-0004反思补充（决定0044）：**独立预运行审查须单独裁定`CONTROL_STRONG_ENOUGH / CONTROL_WEAKENED / UNRESOLVED`。核对同输入/输出能力、状态和预算、主对照的有效/分配参数与实际计算、强稠密保护的能力及公平超参数菜单、tiny-overfit/IID学习和实际主对照OOD余量。后两标签禁止项目正式效果训练/计分；不能把控制训练失败当成候选优势。

| 必填项 | 可核验问题 | 未满足时 |
|---|---|---|
| K操作 | K=1与K>1各有哪些持续状态、独立历史、每token更新、评分/路由/重采样？共同的输出分布族和读出是否相同？仅换mask时估计对象是连接组织，不能自动叫K候选效果。 | 退回设计；不启动资格训练 |
| 匹配账 | 总递推状态加评分/缓存、有效与分配参数、训练样本/更新、内部步数、实际执行训练/推理算子、时延分别如何配？匹配不了的轴怎么限制结论？ | 标资源未识别；不运行正式效应 |
| 强对照/先例 | 实际单流主控制、密集/全读出敏感性、PF-RNN/RIMs/EviTrack/显式滤波的相关性及排除理由是什么？参考K归属需在架构效果**结果前**版本化裁定；纯作者报告/复现不能自动计项目门。 | 只准独立领域轨或退回设计 |
| 实际主控制资格 | 候选提出后冻结有限任务菜单、oracle或受界参考、学习护栏、主对照余量上下界、资格与正式隔离种子/数据、全部尝试保留与资源上限。 | 资格阶段控制地板/天花板、学习失败或泄漏为`CONFIG_QUALIFICATION_FAILED`，关闭该固定配置且不启动正式候选训练；资源匹配失败为`RESOURCE_MISMATCH`，不得作项目因果效果判定 |
| 操作诊断 | 在首次资格数据前给轨迹持久、跨块泄漏、分量坍塌和冗余**各自**的统计量、阈值/不确定区间及`PASS/FAIL/UNRESOLVED`规则。持久性或独立更新失败、功能上仅剩一个状态、跨块泄漏超过预写容差、坍塌或冗余`FAIL`时，性能差仍可报告，但不能计作“维持多条轨迹”Gate1效果；任一`UNRESOLVED`使Gate1因素判`INCONCLUSIVE`。操作`PASS`只确认因子在本候选/数据下实际运行，不证明不同假设语义。 | 未冻结规则或操作失败，不许事后用距离图/干预图补成项目轨迹 |
| 效果与复核 | 唯一主端点、最低有用差、配对CI或等效不确定性、强对照保护、独立复核与负结果分支事前冻结。 | 不计阶段门，保留所有数值 |

候选身份对应不同潜在解释的**删除/置换和语义专化**属于 Gate3 主张；若Gate1协议把这类干预作次级探索，应标明不改变 Gate1 主判。上表的操作诊断只检查被操纵的结构是否真实运行，不把功能语义自动赋给向量。

先例归属三分支目前是**未来具名参考K因素的科学裁定格式，不是现行入口许可**：`PROJECT_ELIGIBLE_FACTOR` 仅在独立审查确认其操纵区别于纯先例包、项目计分/资源匹配及 Gate2 启动条件已事前版本化时可考虑；`FIELD_ONLY` 仅在证据足够且确认只是先例包效果或缺乏可归属的项目差异时使用；关键材料不足为`UNRESOLVED`，不准项目效果训练。现行 `entry_policy.py` 对项目 `reference_k` 无条件返回 `PROJECT_ELIGIBILITY_UNRESOLVED`；要实际让已裁定合格的参考K进入项目QUESTION，**还必须在其任何架构效果结果前**另立版本化项目规则，并同步修改/测试入口策略。这一步未发生，不能从本模板或科学裁定自动推断项目可运行。任何资格不是效果，也不会让Gate1直接通过或启动Gate2。
