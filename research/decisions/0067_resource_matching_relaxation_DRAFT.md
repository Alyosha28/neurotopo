# 决定0067（草案）：资源匹配标准的前瞻放宽——单轴匹配 + 全轴披露 + 条件化判词

2026-09-24。**状态：`DRAFT_FOR_INDEPENDENT_REVIEW`。** 本稿是**规则修订草案**，在独立前瞻审查通过之前**不生效**；它不注册实验、不授权训练、不改变 Gate 1 `NOT_PASSED`、不追认任何既有判词。

## 1. 为什么改

**证据一（先例侧）**：`research/prior_art/design_patterns_synthesis.md` 对仓库已审的 16 条先例记录的综述显示，**没有任何一项先例工作同时匹配**状态、有效/分配参数、样本、更新、执行计算与时延。它们普遍**只匹配一个轴**、其余披露：EviTrack 匹配**推理候选预算**（其机制真正多消耗的那一轴），TRNN 匹配**可训练参数**，PF-RNN 一个都不匹配。**本项目现行要求的四条件合取在先例中不存在。**

**证据二（本项目侧）**：该合取已连续否决约十五个候选（G1-MB/G1-DD/G1-SB/FR-0002/G1-RS v0/EXP-0010/EXP-0012/EXP-0013/GPI-0001…），其中多条是**在没有任何数字之前**被纸面否决的。当约束的交集接近空集时，继续在交集内搜索候选是徒劳的。

**证据三（失败形态）**：EXP-0011 v6 的停止原因是**实测 p50 时延比 1.4811–1.7629 对 1.12 失败线**，而**静态参数、动态状态与线性 MAC 均已匹配**。也就是说，那次失败来自**实现/并行度**，不是科学意义上的资源不对称。

**结论**：放宽的对象应当是**匹配的口径**，而不是**预注册与控制的要求**。

## 2. 三项放宽（R1–R3）

### R1：从"全轴匹配"改为"**单轴匹配 + 全轴披露 + 条件化判词**"

- **主匹配轴**：每个候选在注册时**必须声明该机制相对对照多消耗的那一个轴**，并从以下枚举中选一：递归状态、分配参数、有效参数、训练样本、优化器更新、内部步数、推理候选数、执行 FLOPs。**该轴按预注册容差精确匹配。**
- **全轴披露**：其余各轴（状态、分配/有效参数、样本、更新、内部步数、执行 FLOPs、实测时延）**逐臂测量并以比值报告**，不得省略。
- **条件化判词**：正向结果只能表述为"**在匹配 `<轴>` 的条件下**，候选 ≥ 对照，其余资源比值见报告"，**永远不得**表述为无条件优势。
- **买到什么**：像 EXP-0011 的 K4_score 包、G1-RS 的四流路由这类候选可以真正跑起来；与先例的实际做法一致。
- **代价**：结论强度低于全轴匹配；必须逐条披露不对称。

### R2：**实测时延从"门"降为"报告指标"**，执行计算成为计算轴

- 时延是**系统属性**（kernel 启动、并行度），不是科学资源。在**执行 FLOPs 匹配或如实披露**的前提下，时延只作工程透明性报告，**不再作为停止门**。
- **保障**：执行 FLOPs（或显式的算子级 profile）**必须**匹配或披露；不得用"时延更高但 FLOPs 相同"掩盖实现劣势——该劣势须在结论中明写。
- **买到什么**：消灭 EXP-0011 那一类"静态账目全过、实测时延卡死"的失败。

### R3：允许**带标签的"架构包效应"**（`PACKAGE_EFFECT`）claim track

- 允许把**整个架构包**与最强可得基线比较，判定标签为 `PACKAGE_EFFECT`，**前提**：包的组件被逐一枚举；基线是最强可得的（且按决定0044 不得被弱化）；**不得**声称是哪一组件造成效应。
- **保障**：`PACKAGE_EFFECT` **不能**单独通过项目 Gate 1——Gate 1 仍需隔离因素路线（决定0006/0013 的区分继续有效）。它是**另一条明确标注的主张轨**，不是 Gate 1 的替代品。
- **买到什么**：在干净隔离不可能时，仍能产出**可解释、可发表、标注清楚**的结果，而不是又一次纸面 NO-GO。

## 3. 不放宽的部分（非协商项）

1. **预注册**：假设、对照、种子、阈值、失败分支、禁止推论**必须**在运行前冻结（沿用现行流程与 packet 反思）。
2. **控制不得被弱化**（决定0044）：基线须与候选**同等强度地训练与调参**；"未调优基线胜出"不构成证据。
3. **全轴披露不得省略**：任何"匹配"主张都必须附实测比值；缺一项即视为未披露。
4. **冻结前的廉价筛查保留**：非局部性预筛（秒级）、可压缩性/余量 pilot、预算加倍（仅控制臂）。**它们不是官僚程序**——CAL-0008 与 GPI-0001 各用约 1 分钟与约 9 分钟 CPU 就否掉了会白烧一整轮的设计。
5. **负面与不确定结果保留**；判词四分类不变。
6. **主张范围限于所测**：不得由正效推论候选身份、H3 语义分工、自然任务泛化或任意 K 的普遍规律；不得仅凭模块化/循环获得新颖性。
7. **阶段门不变**：Gate 1 仍 `NOT_PASSED`；Gate 2 不启动；本修订**不**使任何旧候选重开。

## 4. 生效后的判词模板（防止放宽被读成"更容易过门"）

- 单轴匹配结果：`SUPPORTED_AT_MATCHED_<AXIS>` / `FALSIFIED` / `INCONCLUSIVE`，**并强制附全轴比值表**。
- 包效应结果：`PACKAGE_EFFECT_SUPPORTED` / `PACKAGE_EFFECT_FALSIFIED` / `INCONCLUSIVE`，**且明写"不构成 Gate 1 证据、不识别组件归因"**。
- 任何模板都不得省略"未匹配轴"一行。

## 5. 禁止推论

不得由本修订得出：Gate 1 通过或阶段门变化；旧候选（G1-MB/G1-DD/G1-SB/FR-0002/G1-RS/EXP-0010/0012/0013/GPI-0001）重开；"组织有效/无效"的一般结论；先例新颖性；对既有冻结判词的追认。放宽的是**匹配口径**，不是**证据标准**。

## 6. 独立审查须回答的问题

1. 三项放宽是否**在保持内部效度**的前提下可行？特别是 R1 的"单轴匹配"是否足以支撑条件化判词，还是仍会诱导过度归因？
2. R2 把时延降为报告指标、以执行 FLOPs 为计算轴，是否恰当？是否存在"FLOPs 匹配但时延差异暴露真实资源不对称"的反例？
3. R3 的 `PACKAGE_EFFECT` 轨是否会被用作绕过 Gate 1 的后门？标签与禁止推论是否足够？
4. 保留的廉价筛查（非局部性/可压缩性/预算加倍）是否应当一并放宽，还是如本稿所述保留？
