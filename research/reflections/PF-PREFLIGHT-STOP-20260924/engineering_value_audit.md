# 提前 PF-GRU 软件测试的独立工程价值核查

2026-09-24。回应任务后反思的 PF-REF-01/02。本轮只读 `src/neurotopo/`、`tests/`、`scripts/`、`configs/` 的 PF-GRU/粒子/重采样实现标识；实际命中均为统计 bootstrap 或图随机化里的 `resampling`，没有 PF-GRU cell、粒子状态接口或 PF 资源账。`research/prior_art/particle_filter_rnns.md` 已核查作者实现为 GPL-3.0、旧 PyTorch 1.3.1 要求，本项目未复制/安装。因而目前不存在一个待定位的本地 PF 软件故障。

若将来有 PF 代码路径，低成本定义性断言可以是：`[B,K,h]` 粒子与 `[B,K]` 权重维度；权重非负且和为1；给一粒子更高观测似然时其归一化权重按预期变化；软重采样分布 `q=αw+(1−α)/K` 规范化且重要性修正可复算；同一显式 RNG 可重放；评分/转移参数有有限梯度；状态、随机数和执行计算被计入资源账。这些断言将检测**新 PF 实现**的接口、数值与随机性错误；它们不会直接回答 H3-SLOT 的独有计算预测。

现在要运行这些断言，先须设计/实现 PF-GRU 本体、处理重采样梯度与作者代码许可/兼容性，并写测试。这不是给现有模块增加几条测试，成本也没有已注册任务或候选差异来约束；因此没有理由宣称它是当前可立即解除阻塞的低成本工程修复。此判断仅限当下；出现具体 PF 代码错误或独立的软件集成任务时，可单独做工程测试。

**范围修正：**纯独立工程排错若不改变 Gate 1 的资格层、顺序或科学推论，逻辑上无需先版本化 `research/decisions/0006_gate1_baseline_dependency.md`。只有要把 PF-GRU 测试**提前纳入研究 preflight 或用其结果改变 Gate 1 路线**时，才需先版本化科研依赖与该测试协议。原决定0010把所有独立工程测试都写成必须先改依赖，范围过宽，另由 `research/decisions/0011_pf_engineering_scope_correction.md` 正式更正。
