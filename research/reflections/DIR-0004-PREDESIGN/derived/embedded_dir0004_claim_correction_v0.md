# DIR-0004 主张更正 v0：§2 的"可证明分离"改判为"任务侧精度需求无界 ＋ 架构分离待检验"

2026-09-24。**状态：设计稿的自我更正，先于任何独立审查。** 本文不注册实验、不授权训练、不主张 Gate 1、不改变 Gate 1 `NOT_PASSED`、不重开非回归清单任何条目。本文的存在理由：在冻结送审 packet 之前，我按仓库纪律先自查设计稿，发现 §2 的核心措辞**超出了机器核验实际确立的内容**；若照原稿送审，等于把一个未证命题当作已证前提交给审查者。

## 1. 本轮自查发现的三处问题

### P1（实质，最重要）"稠密状态**必然**丢失轨迹"不是已证结论

原稿 §2 写：

> 稠密状态：`H` 个浮点、每浮点有效精度 `b` 比特，总计 `bH` 比特的**对称**预算。它必须在每一步为**全部** `m` 个方向保留精度，包括**收缩方向**……因此在 `T*` 之后，稠密状态**必然**丢失轨迹。这是算术，不是我的希望。

核对结果：机器核验（`scripts/dir0004_precision_check.py`）的模型类**就是**"每个坐标一个固定 `b` 比特精度"的存储模型，而"对称分配"在该模型里是一个**参数选择**，不是"稠密状态"的推论。一个稠密状态至少可以做两件被原稿排除的事：

1. **不存储可观测的收缩分量**——它每一步都被观测重新给出，精度由观测而非存储决定（核验里 `contracting_bounded` 对 `delta ≤ 13` 恒为 `true`，正说明收缩侧的比特数几乎不进入误差）；
2. **把全部容量用在隐藏的扩张分量上**——同一个标量可以用多个单元承载（定点/多单元码），这不需要任何"结构声明"。

所以"必然"只在**声明的每坐标固定精度编码**这一模型类内成立；把它读成"任何 `H` 个浮点的稠密状态都必然丢失轨迹"是**过度主张**。更严重的后果是**对照被削弱**：用"被强制对称分配"的臂去比"被允许非对称分配"的臂，是仓库已多次否决的弱对照（EXP-0011 v6、GPI-0001、G1-ALIGN-0001 的教训都属此类），而 Gate 1 的证据标准不因 0069/0080 的放行而降低。

### P2（口径）`predicted_gain_steps` 用了方差口径，与实测差 2 倍

旧 `dir0004_precision_check.json` 报 `predicted_gain_steps = 15.5` 而 `horizon_gain_steps = 31`——一个在 packet 里会被审查者正当地读作"预测失败"的数字。根因：公式分母用了 `2·ln(λ_u)`（方差口径），而阶梯量的是幅度口径 `ln(λ_u)`。

已修：`predicted_gain_steps = 31.0` 与实测 `31.0` 一致；同一处把含糊的 `theoretical_bits_per_step` 拆成两个显式标签 `theoretical_bits_per_step_amplitude = 1.0` 与 `theoretical_bits_per_step_variance = 2.0`；旧稿里定义草率的 `fit_bits_vs_T_slope`（0.0644，前一轮已声明不引用）**删除**，§4 要求的 bits(T) 曲线改由新脚本产出（见 P3）。

### P3（我自己的筛查脚本参数化错误）控制组退化为隐藏组

第一版 `scripts/dir0004_affordance_screen.py` 取 `eps = 1e-6`、`sigma = 1e-3`。被观测的扩张模态后验方差**下限是 `sigma² = 1e-6`**，而达标线是 `eps² = 1e-12`——即**任何比特预算都不达标**，"观测控制组"于是与隐藏组给出**逐点相同**的曲线（slope 都报 1.0）。这不是任务属性，是参数化错误，而且恰好会把"隐藏模态是必要条件"这一结论变成同义反复。

已修：屏幕默认改为 `sigma = 1e-6`、`eps = 1e-3`（满足设计 §1 明写的"观测信息量足够"），并新增 `observation_informative_enough_for_control`（要求 `sigma ≤ eps/10`）；不满足时 `control_verdict` 直接报 `OBSERVATION_NOT_INFORMATIVE_ENOUGH` 并**拒绝**给出控制判词，而不是静默返回一条退化的控制曲线。

## 2. 更正后的主张（设计 v0.1 用）

- **C1（任务侧，已核验，可作注册预测）**：隐藏不稳定模态的跟踪所需**存储精度**随视界线性增长，斜率 `log2 λ_u` 比特/步。
  - 线性（`λ_u = 2`，`σ = 1e-6`，`ε = 1e-3`，`T ∈ [4,64]` 步长 4）：斜率 `1.000`，配对 bootstrap 95% 区间 `[1.000, 1.000]`，最大残差 `< 1e-13` 比特，`R² = 1`。
  - 控制（同参数、扩张模态每步被观测）：最小比特数在全部 `T` 上恒为 `9`，斜率 `0`，`control_verdict = BOUNDED` ⇒ **"扩张方向不可观测"是分离的必要条件**（第 1 轮偶然发现，本轮成为屏幕自带控制）。
  - 非线性复现（引自已审工件 `dir0004_nonlinear_bitcheck.json`，sha256 随屏幕记录）：帐篷 `1.030`、逻辑斯蒂 `r=4` `1.073` 比特/步（两者 `λ = ln 2`，预测 `1`）。
  - 结论：该任务族**不存在有界维、有界精度的精确解**——这正是 CAL-0008 留下的开放问题（"精确解本身不可用低维平滑近似"）。
- **C2（架构侧，未证，必须由资格阶梯第 1 级判定）**：在匹配状态预算下，"显式扩张/收缩组织"是否买到更长的可跟踪视界。C1 **不蕴含** C2：C1 只说任务需要多少精度，不说哪种组织能拿到它。任何把 C2 写成 C1 推论的行文都是过度主张。

因此 v0.1 的 §2 标题与措辞按此改写，且 §5 的第 1 级（oracle 拟合探针）由"保险"升格为**唯一能产生架构分离主张的闸**；它失败即回第 0 步，不得靠延长预算或换配置救。

## 3. 前置文献（本轮补做，见 `research/prior_art/dir0004_chaos_tracking.md`）

原稿 §9 自认"与精度/混沌跟踪直接对应的定理级来源未取回"。本轮已补：

- **AUS（assimilation in the unstable subspace）是成熟领域**（Trevisan/Carrassi 等，2004–2017 一串高引论文），其核心主张正是"把状态/分析限制在不稳定子空间"。故 C2 即便成立，也只是**该思想在匹配状态预算下的受限定量命题**，不得主张机制新颖。
- **C1 与教科书可预报时间公式 `T_p ≈ (1/λ)·ln(Δ/δ)` 等价**（单位换算），同样不得主张新颖——它是**任务侧事实**，不是本项目的发现。

两条并入设计 §3 的"先例边界"。
