# CO的ln2误差平台：输出二值分量未解决

2026-09-28。EXP0017既有预测的事后诊断；设计在读取分量指标前单独冻结于`873feb7`，但假设来自已知联合KL，不能称未暴露数据上的验证。局部描述判词 **SUPPORTED / POSTHOC_OUTPUT_BINARY_UNRESOLVED**；不改变EXP0017的INCONCLUSIVE / LEARNING_FAILURE。

## 结果

对D64全部3seed×IID32/OOD128，逐例做精确链式分解：

`−log p(j*,b*) = −log p(j*) −log p(b*|j*)`。

| D64，三seed均值 | IID32 | OOD128 |
|---|---:|---:|
| 原联合KL/NLL | 0.70091113 | 0.70123181 |
| j边际NLL | 0.00303045 | 0.00309567 |
| 给定正确j的b条件NLL | 0.69788067 | 0.69813614 |
| j准确率 | 100% | 100% |
| 给定正确j的b准确率 | 50.2604% | 50.6104% |

| p(b=1|正确j)偏离0.5的平均绝对值 | 0.03845 | 0.03894 |

全部六个D64组通过事前写下的描述判据；没有用聚合均值遮盖某个失败seed。反向分解也一致：b边际NLL为.69786298/.69810182，给定正确b的j条件NLL仅.00304814/.00312998。这排除了“只是联合关联错而两个边际都正确”作为主要输出误差解释。

D16锚点呈相同方向：IID/OOD的j准确率100%/99.9674%，b条件准确率50.4557%/50.1790%，二值条件误差占比分别97.9498%/97.8349%。单纯将状态16扩大到64在已测试预算下没有解除二值输出问题；不是容量一般无效的结论。

## 得到了什么信息

CO定义中r只将j加1 mod3，s只翻转b，因此`j=#r mod3`、`b=#s mod2`。本轮所测最终输出对j几乎没有误差，对b仍接近均匀预测；联合KL接近ln2有明确的分量解释，不只是误差总和巧合。更精确的描述是：**已测试CO模型的最终输出没有可靠解决s的奇偶分量，而j分量已经预测正确。**

这项证据把问题从笼统的“整个六状态任务没学会”收窄到一个具体运算分量。它没有定位内部原因：隐状态可能没有形成该信息，也可能编码了但现有读出未利用，或者训练还没有找到有效解。没有hidden干预、重新拟合读出、训练干预或额外模型执行，故不能在这些解释间作因果选择。

主代理在分解后补充的设计限定（不是新数值结果）：原任务每4步输入的sensor为`1[j=0]`，直接提示j而不直接提示b；训练软标签则同时监督完整(j,b)。因此j与b的结果差异还混有输入端状态提示的不对称，不能据本轮断言“模2运算天然比模3难学”或唯一原因是不能形成符号翻转。输入提示、动态保持、优化与读出的解释仍需区分。

同样不能由约50%准确率证明统计独立或总体严格随机；p(b=1|j*)确有约.038的平均偏离。本轮使用的是预写的描述阈值，不是总体等价检验。100% j准确率只覆盖保存的有限样本，不证明任意长度的正确算法。
