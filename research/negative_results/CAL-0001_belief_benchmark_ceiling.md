# CAL-0001: the known-reliability belief task saturates

2026-09-24. **Engineering calibration, not a registered Gate 1 architecture experiment.** Design: `research/design/gate1_belief_benchmark_calibration.md`; complete per-seed record: `artifacts/calibration/gate1_belief_v1.json`. The runner and all three fixed model seeds completed. No multi-trajectory model was trained or compared.

Four hypotheses, six informative cues with displayed reliabilities and six tagged distractors gave the intended nontrivial *label* task on the separate 8,192-example calibration stream: exact Bayes MAP accuracy 88.07%, last-cue accuracy 59.64%, early-posterior-only accuracy 74.18%, and early→final Bayes MAP changed on 22.41% of examples. The analytic oracle's true-label NLL was 0.3346 nat. Thus the last-cue shortcut did not solve the task and noisy labels left substantial error relative to 100% accuracy.

Nevertheless the strong single-state dense GRU reached the analytic posterior. At the fixed 1,500-update budget, final KL(target posterior ‖ GRU posterior) was **0.000542 / 0.000288 / 0.000339 nat** for seeds 101–103, all far below the plan's 0.01-nat saturation threshold. Final true-label accuracies were 88.16% / 88.00% / 87.95%, essentially at the oracle's 88.07%; final NLLs were 0.3350 / 0.3352 / 0.3351. The task is therefore **not qualified** as a discriminating Gate 1 benchmark at this configuration. The runner records source/script hashes, dirty worktree, data seeds, monitoring curves, parameter and operation accounts and all three outcomes. These are calibration observations, not publication-level independent replications.

The design error is identifiable: the latent truth is fixed and each cue's reliability is explicit. Four accumulated log weights are sufficient to update the full posterior, well within H64. Adding observational noise lowers the Bayes accuracy but does not create architectural headroom. Raising temperature, adding more distractors or selecting a favorable test delay after these results would not repair that construct problem.

Reaction: retire this configuration before any M3-versus-control comparison. A new calibration should hide a task-relevant source/context variable, making the sufficient state a *joint* distribution over content and source hypotheses; retain an exact oracle and strong single-state baseline. First use an analytic simulation to check the last-cue, source-only and previous-belief shortcuts, then train only a conventional GRU on disjoint calibration streams. A multi-trajectory result remains untested and Gate 1 remains NOT_PASSED.
