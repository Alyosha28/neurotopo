# Gate 1 belief-update benchmark calibration plan

2026-09-24. This is a **calibration plan**, not a Gate 1 experiment or an architecture result. Its sole question is whether a known-posterior evidence-update task defeats the last-cue shortcut while leaving a learned, strong single-state GRU measurable room below the analytic oracle. The causal chain under examination is evidence stream → recurrent dynamics → belief readout → decision accuracy. No adaptation, communication, biological graph or DARC is introduced.

Prior-art check: `research/prior_art/belief_update_benchmarks.md`. Strongest rejection: the exact Bayesian filter needs only four accumulated log weights, so a 64-state GRU may learn it almost perfectly. Merely lowering the Bayes-optimal **true-label accuracy** with noisy evidence would not create architecture headroom if the GRU already matches the oracle posterior.

## Frozen exploratory generator and split

- Four latent hypotheses, uniform prior. Each episode has three early and three late evidence tokens. A cue names one of four hypotheses; its observed reliability is chosen uniformly from 0.45, 0.60 and 0.75. Conditional on the true hypothesis, the cue is correct with that reliability and otherwise names one of the other three uniformly. Each evidence token is followed by one tagged distractor whose cue and reliability are independent of the latent hypothesis. A query follows the early segment and another ends the episode.
- Exact posterior after either query is `softmax(sum_t log[P(cue_t | H=k, reliability_t)])`, summing only tagged evidence. The target is the full posterior plus the sampled true hypothesis for descriptive accuracy. No late selector, candidate-value permutation or label-containing query exists. A last-evidence-only rule, early-posterior-only rule and uniform rule are shortcut controls.
- `np.random.Generator` is supplied explicitly. The exploratory analytic stream uses seed 19001 (already inspected before this written plan); GRU calibration training streams use `191000 + model_seed` for seeds 101–103, validation seed 192001, and test-like calibration seed 193001. None of these streams may be reused in a later formal architecture comparison. Different splits are regenerated from independent RNGs.
- The exact oracle and shortcuts are checked on at least 20,000 calibration episodes. The dense H64 GRU uses the existing cell with the new input size, two posterior cross-entropy readouts, batch 128, Adam 0.003, gradient clip 1 and 1,500 updates per seed. No checkpoint selection; report results at the final update and learning curves at 500/1000/1500 on validation only. This is an engineering calibration, not a pre-registered performance claim.

## Diagnostic outcomes and decision

Report oracle and shortcut true-label accuracy and NLL, oracle pre→final MAP-change rate, and per-seed GRU cross-entropy **excess over oracle entropy** (KL to the analytic posterior), MAP agreement with the oracle, true-label accuracy, runtime and parameter/state/operation accounts. A non-ceiling Bayes true-label accuracy by itself is insufficient: if the GRU's final KL is near zero (operationally below 0.01 nat), the task is saturated for this baseline. If final KL exceeds 0.20 nat or oracle-MAP agreement stays below 0.70 after the fixed budget, learning is inadequate. The interval between those diagnostics only licenses designing a separate matched architecture experiment; it does not pass Gate 1. Store every seed and do not choose a favorable difficulty slice after reading results.

The exploratory 100,000-episode analytic simulation with seed 19001 (without distractor tokens, which the oracle ignores) found approximately 74% early oracle true-label accuracy, 88% final accuracy, 60% last-cue accuracy and 22% pre→final MAP changes at three-plus-three evidence tokens. These figures motivated the frozen configuration; they are calibration observations, not held-out evidence. If the trained GRU saturates or fails to learn, record that design failure and revise the generator/training protocol explicitly before any architecture run.
