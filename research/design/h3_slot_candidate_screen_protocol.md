# SCR-0001：身份条件化证据评分槽的零训练机制筛查

2026-09-24，在查看此候选筛查结果、写实现或运行新任务之前固定。本协议回应 `research/decisions/0006_gate1_baseline_dependency.md` 的当前缺口；它不是 EXP、不是 Gate 1 实验，也不授权模型训练。只检查一个具名的、无适应/重采样/跨候选通信的候选：**H3-SLOT**，即 `K` 个带可命名身份的循环槽，输入证据对各槽产生分数，归一化权重读出。选择它是因为它最接近当前 H3 文字定义，最容易被简单滤波、PF-GRU 或 RIMs 解释掉；筛查失败是有价值的停止证据。

## 唯一问题和最强反驳

问题：H3-SLOT 是否能在不引入后续阶段机制的前提下，写出一个相对解析滤波、带权粒子/PF-GRU、选择性模块/RIMs 和等状态单流 GRU **独立可测、可消融的新增预测**？

最强反驳：候选槽若按假设身份固定并累加证据评分，就是显式离散贝叶斯滤波或混合专家；若槽随机传播并重采样，就是 PF-RNN；若输入注意选择更新、模块稀疏通信，就是 RIMs。删除预先标号槽导致同名假设受损是硬编码后果，不是学出的功能特异。

## 事前固定的筛查输入与交付字段

只使用当前 `research/hypotheses.md`、`research/design/h3_candidate_trajectory_contract.md`、PF-RNN/RIMs 原论文及仓库既有先例审计，不看新任务分数、不写代码。交付一页以上的 `research/evidence/h3_slot_candidate_screen.md`，逐项给出：

1. 完整的单步状态转移和读出方程：`C_t`、每个 `Z_t^k`、权重 `w_t^k`、身份编码、证据评分、更新/不更新规则；明确随机性、监督信号与是否共享参数。
2. 至少一个指定潜在变量、证据流和输出目标的任务族，解析或可界 oracle、最小充分统计量及简单滤波解。若任务仍是当前四/八状态后验问题，要解释为什么强单流 H64 GRU 的既有近 oracle 结果不使其饱和。
3. 对解析滤波、PF-GRU、RIM 风格机制和等总动态状态单流 GRU 各写一个**同输入、同资源定义下的反事实预测**，注明哪一项是该候选独有、方向如何、至少多大差异才有用及哪项消融能否定它。未给数值阈值、无可测输出或只改术语均记为缺失。
4. 列出总动态状态 `C+K×Z+K`、有效/分配参数、评分/路由/重采样与训练/推理计算的匹配口径；说明输入硬编码、共享读出或额外监督能否单独解释预期收益。
