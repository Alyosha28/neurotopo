# CAL-0008 末端余量筛查：独立预运行审查说明（事前提交）

2026-09-24。本说明在**注册运行之前**提交，规定本轮独立审查要回答什么、依据什么、不得得出什么。它不是效果证据、不是注册、不是 Gate 通过或实验许可。

## 问题

1. 该筛查的设计能否**判定**"资源匹配的稠密单流控制在注册预算末端是否饱和"？判据（`ε_abs=0.05` nat、`ρ=0.05`、`κ=0.90`、`τ_plateau=0.01` nat、`LR_TOL=0.02` nat、未训练下限 `0.10` nat 与良态上界 `ln 2^M + 0.5` nat、跨 LR 一致门、逐 seed 聚合与选定 LR 绑定、3 seed t 区间）是否足以支撑 `HEADROOM` / `SATURATED` / `LEARNING_FAILURE` / `INCONCLUSIVE` 四分支？
2. 固定**四项**配置菜单（`C1` M=4/T=16/λ=0.7 仅管线健全性、`C2` M=8/T=16/λ=0.7 容量轴、`C3` M=8/T=32/λ=0.4 视界轴、`C4` 阻挫有符号图）是否**足以回答**"是否存在保留末端余量的可接受任务配置"，且不构成被禁止的任务搜索？C1 仅作管线检查、永不作为答案，是否足够？
3. 是否存在会使结果不可解释的实现或设计缺陷：oracle 正确性、软目标与 KL 计算、控制是否被欠调参（从而制造假余量）、数据流与评估流是否分离、配置间难度是否可比、以及"控制取最优 LR"是否确实保守？

## 输入范围

送审 packet 只含：本审查说明、筛查设计全文、工程核对输出（oracle 第二实现结果与 200-updates pilot 记录）。评审者**不得**浏览仓库其他内容、不得读取对话、不得运行代码或训练。

## 最强拒绝（审查须正面处理）

- **R1**：余量可能是控制欠训练/欠调参的产物 → 设计用最优 LR、`B=4000`，并以 C1 锚点校验预算是否足以学透同族任务。
- **R2**：`M=8` 时 oracle 或 KL 实现有误，导致"余量"是 bug → 已用轨迹枚举第二实现核对（工程输出已附）。
- **R3**：菜单虽固定为 **4 项**（`C1` 管线检查、`C2` 容量轴、`C3` 视界轴、`C4` 阻挫），但"挑到有余量的配置"仍是选择偏差 → 设计规定全部报告、按预注册顺序 `C2→C3→C4` 取第一个过门者、`C1` 永不作为答案、不追加 `M/T/λ/β/J` 搜索。
- **R4**：本筛查与架构效果无关，可能被误用为 Gate 1 证据 → 设计已声明禁止该推论。
- **R5**：`ε_abs=0.05`、`ρ=0.05`、`κ=0.90`、`τ_plateau=0.01`、`LR_TOL=0.02`、未训练下限 `0.10` 的取值依据 → 绝对量级参照既有记录（CAL-0006 的 `0.08`、EXP-0009 的 `0.07`）；相对与平台门槛由三轮预运行审查引入。

## 判定规则

三项问题各给结论；整体给 `READY_TO_RUN` / `REVISE_BEFORE_RUN` / `REJECT` 之一。任何"通过"**不得**被读作实验许可、Gate 1 通过、候选有效性、先例新颖性，或对既有冻结判词的追认。

## 禁止推论

不得由本轮审查得出 H3 一般证伪、阶段门状态变化、"多轨迹组织必然有效"，或要求以放宽资源/控制匹配换取 `READY_TO_RUN`。

## 第二次审查（针对修订版 v2）：逐条核对下列 8 项要求是否落实

第一轮判词为 `REVISE_BEFORE_RUN`，要求：(1) 完全指定决策统计量（末步后验 KL、held-out episode 数、n=3 的区间估计量，并把 episode 级蒙特卡洛误差与 seed 离散分开报告）；(2) 门槛按配置归一化（相对 + 绝对双门），使 `M=8` 不因 `ln 2^M` 尺度获得更大自由残余；(3) 注册 250/500/1000/2000/4000 的平台/收敛检验，仍在下降者判 `INCONCLUSIVE` 而非 `HEADROOM`；(4) 拆开 `M/T/λ` 混淆（补 `M=8` 在 C1 的 `T,λ` 下的点，或预先禁止因果读法）；(5) 把 oracle 核对扩到生产视界（独立实现，逐时步一致）并公布 KL 与软目标归一化检查；(6) 在运行前固定 LR 规则（在独立训练侧流上选取、说明逐 seed 还是逐配置、报告落选 LR）；(7) 降低 C1 的报地位（仅管线健全性，且不得作为余量答案）；(8) 在注册可行性与计时外推前，对将要运行的配置（`M=8, T=32`）做 pilot。

**第三轮（针对 v3）**：第二轮判 `REVISE_BEFORE_RUN` 并要求六项修正：(a) 恢复并使用完整收敛网格、把平台判据改为**双侧且分层级**、并指明检查点 KL 在哪个流上测量；(b) 明确 `ρ/κ` 的 seed 聚合层级并给未训练 KL 分母设下限；(c) 修正判词分支，使"学不会"判 `LEARNING_FAILURE` 而非落入预算 `INCONCLUSIVE`；(d) 扩大 LR 规则或增加"残余对 LR 不敏感"的门；(e) 公布软目标归一化与 KL 检查及生产视界逐时步一致性；(f) 把审查说明自身的问题与阈值更新到 v3（删除 `Δ_min=0.10` 与三配置菜单）。

审查者应逐条判断"已落实 / 部分落实 / 未落实"，并给出整体判词 `READY_TO_RUN` / `REVISE_BEFORE_RUN` / `REJECT`。注意：工程 pilot 的 KL 数值**不得**被当作末端余量的证据；packet 内所有 pilot 行仅为工程健全性与计时用途。
