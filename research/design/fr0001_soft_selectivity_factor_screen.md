# FR-0001：两模块软选择更新的可注册性筛查

2026-09-24，在实现任何新模型、读取其性能或开启 EXP 迭代前固定。**唯一问题：**能否在旧 EXP-0004 延迟绑定/修订任务上，以相同输入、状态、参数、训练样本、内部步数和实际执行路径，单独比较两个 recurrent 模块的**更新选择性强度**？若设计可行，后续研究仍是 `independent_benchmark` 的领域软路由因素，不是项目 Gate 1、H3 语义或 RIMs 论文复现。相关一手边界见 `research/prior_art/fr0001_soft_routing_scope.md`；旧任务的 OOD32 主控制余量与缓存简单解已知，不能当未触碰的新 benchmark。

## 候选操作与资源

拟议相同 H64/K2、各宽32的分块 GRU 骨干；所有块每 token 都按原输入 `x_t` 和自己的旧状态**计算** 候选更新 `h_proposed^1,h_proposed^2`，不通信、不加适应。共享一个 `Linear(input_size=13,1)` 路由器给出 `q_t=tanh(vᵀx_t+b)∈(−1,1)`。对预定温度 `τ`：

```text
g_t^1 = sigmoid(q_t / τ)
g_t^2 = 1 − g_t^1
h_t^k = h_(t−1)^k + g_t^k (h_proposed^k − h_(t−1)^k)
```

两臂只改 `τ_low=0.2` 与 `τ_high=2.0`；`g1+g2=1`、各门在[0,1]，每 token 总更新权重固定。两臂同初始化张量、同 batch/种子、同 router 输入、同状态和权重拓扑、同全部 proposed 更新/路由运算；不会把“被弱更新的块省了 FLOPs”作为结论。`tanh` 限制 logit 范围，使高温臂即使放大参数也不能复制低温的极端门控；无温度以外的层、输入或损失差异。`RecurrentModel` 的 K2 block mask 与 H64 readout可复用，但须单列新 router 的14个分配/有效参数、每例64递推状态、早期4维输出缓存、路由门与门控乘加/非线性/运行时间；当前 `resource_account` 的旧前向线性代理不能冒称完整执行 FLOPs。

## 固定任务与可否定预测

仅用既有 `src/neurotopo/task.py::make_batch` 的四候选绑定、早 query 与晚 selector；训练噪声任务，照 EXP-0004 的 delay0×2000、2×1000、4×1000、8×2000 课程、Adam0.003、batch64、clip1、CPU单线程，最终评估 delay8/32/64。温度臂唯一主比较若继续，将在**新配对种子**的 OOD32 joint-pair accuracy 中预写 `low−high` 的有用方向为至少+3百分点；delay8 只作两臂学习护栏，delay64 为次级稳健性，不因结果移动主端点。需预写每种子门控分布/熵操纵检查，证明低温实际更选择性；若训练让 `q≈0`，性能比较不能解释为选通强度差。因旧 EXP-0004 已用于启发本问题，任何正效应只能是同任务族的受限机制证据，须另有预定独立任务/种子复核才能声称跨任务泛化。

真正训练前须先对**实际主对照 τ_high**在隔离的资格种子下检查：delay8 pre≥0.90 与 joint≥0.50 每种子、OOD32 mean joint accuracy∈[0.10,0.85]、且预设门控分离量达标；失败则停止此模型/任务规格，不换τ、delay或 task payload。正式效应种子与资格种子互不重合，固定任务菜单只有这一项；状态/分配与有效参数/训练样本/实际执行 FLOPs/时延逐项报告，主比较用配对训练种子和预写 CI。所有门槛、种子、运算计数及结果分支必须在未来版本 EXP 协议**实现和训练前**冻结；本筛查本身不授权训练。

最强反驳：温度改变梯度、门控熵和状态保留速率，若 low 胜 high，也无法唯一解释成“模块学会竞争假设”；旧任务可缓存、selector 直接指名，最多测延迟记忆/检索。反过来，high 路由器可能通过其他表示补偿温度；若门控熵未真正分离，则实验操纵失败。该对照仅隔离**已定义温度驱动的软更新门控 package**，不是 RIMs 的稀疏计算或通信，也不是 K 数目的纯因果效果。需要独立批评确认它仍有可测增量决策价值，且实际主控制、已选任务和资源账不会把效果误归因于更多输入或计算。

判 `FACTOR_SPEC_READY_FOR_REGISTRATION` 仅当上述算子、对照、任务、门控操纵检查、资源/时间和失败条件可在一份无事后自由度的新 EXP 协议中补齐并有独立预运行批评；这**只允许**按 `independent_benchmark` 开启 QUESTION/注册，不保证资格通过或项目 Gate 1。若温度虽同资源但无法保证可测门控分离、实际执行差异无法匹配、对照不是独立可学，或任务主端点不能支持所声称因素，判 `NO_CLEAN_FACTOR_NOW` 并不训练。若仍缺源码/算子信息，则 `INCONCLUSIVE`，保留缺项。不因 old M3 负效应挑温度或事后更换任务。
