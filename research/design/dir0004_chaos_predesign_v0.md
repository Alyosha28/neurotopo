## 0. 为什么是这个任务族

过去九个任务族全部死在"任务侧没有空间"：CAL-0001/0002、EXP-0009、CAL-0008 的精确解都是 4–8 维充分统计量（TH-0001），匹配的稠密控制直接算到 oracle（KL 0.0003–0.0038 nat），组织没有可买的东西。CAL-0008 已实测关闭"同族加难"这条路。**唯一没被否证的出路是换一个"精确解不存在有界维充分统计量"的任务类**——即 CAL-0008 留下的开放问题。

本稿选**混沌潜轨迹跟踪**：它的精度需求随视界线性增长，因此**不存在有界维精确解**（这正是筛查闸要的形式），同时它给出**可证明的表示分离**，而不是靠调参制造。

## 1. 任务类规格（待冻结）

- **潜状态**：已知混沌映射 `z_{t+1} = F(z_t)`，`z ∈ R^m`，最大 Lyapunov 指数 `λ > 0`（候选：帐篷映射/逻辑斯蒂映射的耦合格，`m` 与 `λ` 事前固定）。
- **观测**：`y_t = H z_t + η_t`，`η ~ N(0, σ²I)`，`σ` 事前固定；观测**信息量足够**确定潜状态到所需精度（否则分离来自"观测信息"而非"表示"，那会退回旧病）。
- **oracle**：真实潜轨迹 `z_t`（以及其后验方差解析式，用于 oracle-relative KL）。
- **终点**：末端 `KL(p_模型 ‖ p_oracle)`；不用任何时间量终点（避开决定0062 B）。

## 2. 两条分开的主张：C1 任务侧（已核验）与 C2 架构侧（未证）

> **v0.1 更正**：本节的标题原为"可证明的分离（本设计的核心）"，并把下面第 2 段读成"稠密状态**必然**丢失轨迹"。那句话只在**声明的每坐标固定精度编码**这一模型类内成立（见下），不足以支撑"任何同样 `H` 个浮点的稠密状态都必然丢失轨迹"。据此把主张拆成 C1 与 C2。

设目标为在视界 `T` 内以精度 `ε` 跟踪潜状态。混沌放大使所需精度按
`bits(T) ≈ (λT + ln(1/ε))/ln 2`
增长（每步约 `λ/ln2` 比特）。

### C1（任务侧，已核验）：精度需求随视界无界增长

**在核验所用的模型类内**（潜状态两维，扩张分量隐藏、收缩分量每步被观测；每个坐标以固定 `b` 比特精度存储，量化方差 `q²/12`，`q = 2^-b`）：

- **稠密（对称）编码**：把 `bH` 比特平均分给全部方向。收缩方向的比特几乎不进入误差（它每步被观测重新确定），所以真正的代价是扩张方向只拿到一半比特。
- **非对称编码**：把比特集中到隐藏的扩张方向，收缩分量由已知映射与观测重新导出。

在该模型类内，`T* ≈ (bH − log2(1/ε))·ln2/λ`；对称分配在 `T*` 后丢失轨迹，非对称分配在**同一总预算**下把可跟踪视界按比特比放大。

**但"对称分配"是这个模型类的一个参数选择，不是"稠密状态"的推论**：一个稠密状态**可以**（i）完全不存储可观测的收缩分量（每步的观测重新给出它），也可以（ii）用多个单元承载同一个隐藏标量（多单元定点码），从而**不需要任何结构声明**就得到非对称分配。因此 v0 的"必然"是过度主张，且会引出**稻草人对照**——用"被强制对称分配"的臂比"被允许非对称分配"的臂。C1 只说明**任务需要多少精度**，不说明**哪种组织能拿到**。

- **oracle 臂**：把真实扩张子空间坐标直接供给同一架构（对应 E 区 `GT-Modular` 装置）。

**必要条件（第 1 轮机器核验后新增，原稿遗漏）**：分离**只在扩张方向不可观测时成立**。若每步都能观测到该方向，观测会把状态重新定位、误差方差饱和于 `σ²`，两种比特分配都不失效（对照运行 `--observe-expanding` 得 `T* = NaN`）。**本轮把这一条做成了屏幕自带的控制**：参数满足观测信息量条件（`σ ≤ ε/10`）时，被观测的扩张模态所需比特数在全部视界上恒为 `9`、斜率 `0`（`control_verdict = BOUNDED`）。因此本任务族规定：**潜状态含一个隐藏的不稳定模态**（`λ_u > 1`、不可观测），收缩/可观测部分照常观测。

**已核验的定律**（`scripts/dir0004_precision_check.py` → `research/design/dir0004_precision_check.json`，线性映射 + 高斯/量化噪声，`λ_u = 2`，总预算 64 比特，`ε = 1e-6`）：对称分配（扩张方向 32 比特）可跟踪 `T* = 14` 步；把比特全部移到扩张方向（63 比特）得 `T* = 45` 步——**同一总预算下视界提升 3.2 倍**；阶梯显示**每多 1 比特恰好多买 1 步**（`predicted_gain_steps = 31.0` 对实测 `31.0`；v0 的 15.5 是方差口径错误，见更正记录）。

**第 0 步筛查的显式数值形式**（`scripts/dir0004_affordance_screen.py` → `research/design/dir0004_affordance_screen.json`，`σ = 1e-6`、`ε = 1e-3`、`T ∈ [4,64]`）：维持精度所需的**最小存储比特数** `b(T)` 的拟合斜率 `1.000`（配对 bootstrap 95% 区间 `[1.000, 1.000]`，最大残差 `< 1e-13` 比特，`R² = 1`），与 `log2 λ_u = 1` 一致；非线性复现引用已审工件（帐篷 `1.030`、逻辑斯蒂 `r=4` `1.073` 比特/步）。故**不存在有界维、有界精度的精确解**。

### C2（架构侧，未证）：匹配预算下的组织收益

> **在匹配状态预算下，一个被声明为"扩张/收缩组织"的架构，是否比一个未被这样声明的稠密控制更接近 oracle？**

C1 **不蕴含** C2。这是本设计**唯一**可能产生 Gate 1 内容的命题，也是 §5 第 1 级（oracle 拟合探针）要判定的对象。若第 1 级显示匹配控制也能拟合 oracle，则本设计没有可注册的内容，按 §7 关闭。

**事前可算的预测**（本设计要冻结的量）：`T*`、两条 `KL(T)` 曲线的**交叉位置**、以及交叉后稠密侧的**发散形状**。终点仍是末端 `KL`（见 §5 与决定的终点规则），交叉位置**只作描述量**，不承载判词——`T*` 是 steps-to-threshold 型量，按 DIR-0003 C 区审计结论会触发决定0062 B，本项目轨**不得**采用时间量终点。

## 3. 声明的机制（必须与任务同时声明）

**显式的扩张/收缩状态组织**：状态被声明地划分为两部分，一部分承载扩张子空间坐标、另一部分承载收缩分量（后者由映射重导出而非存储），并带一个声明的时间尺度/增益分配。oracle 版本直接给出真实扩张坐标。

**先例边界（不得主张新颖性；v0.1 按本轮先例核查改写）**：**不稳定子空间同化（AUS, assimilation in the unstable subspace）是成熟领域**——`On the Kalman Filter error covariance collapse into the unstable subspace`（2011, `10.5194/npg-18-243-2011`）、`Four-dimensional variational assimilation in the unstable subspace and the optimal subspace dimension`（2010, `10.1002/qj.571`）、`Lyapunov vectors and assimilation in the unstable subspace: theory and applications`（2013, `10.1088/1751-8113/46/25/254020`）等已确立"把状态/分析限制在不稳定子空间"这一原则，并讨论过最优子空间维数。故**"收缩方向不值得存储"不是本设计的观察**，C1 亦等价于教科书可预报时间关系 `T_p ≈ (1/λ)ln(Δ/δ)`（`Predictability: a way to characterize complexity`, 2002, `10.1016/s0370-1573(01)00025-4`）。储备池/回声状态、混沌预测、S4/线性动力学模型同属先例。本设计的主张**仅限 C2**："在**匹配状态预算与执行计算**下，被声明为扩张/收缩组织的架构是否更接近 oracle"这一受限的架构/优化问题，且必须写明算法类的正则性假设（否则按 B 区审计结论，该主张在理论上不可证伪）。**逐字标题、DOI 与检索通道事实见 `research/prior_art/dir0004_chaos_tracking.md`（本轮证据为元数据级，正文未读）。**

## 4. 第 0 步筛查闸（在任何架构比较之前执行）

对任何候选任务族，先算：
1. 最小充分统计量维数 `D`（解析或受界 oracle）；
2. `D` 是否随视界/T 无界增长；
3. 若 `D` 有限且 `D ≪ H` → **该任务族立即关闭**（不进入任何训练）。
本任务族的 `D` 按 §2 无界；**该结论已由独立脚本给出可核验的数值形式**（v0.1 补齐）：`scripts/dir0004_affordance_screen.py` → `research/design/dir0004_affordance_screen.json` 给出**维持精度所需最小存储比特数 `b(T)` 的显式曲线与拟合斜率**——斜率 `1.000`（bootstrap 95% 区间 `[1.000, 1.000]`，最大残差 `< 1e-13` 比特，`R² = 1`），与 `log2 λ_u` 一致；同一脚本自带**观测控制**（同参数下被观测的扩张模态所需比特数恒为 `9`、斜率 `0`，`control_verdict = BOUNDED`），并引用已审的非线性复核（帐篷 `1.030`、逻辑斯蒂 `r=4` `1.073` 比特/步）。`screen_valid = true`。

## 5. 资格阶梯（顺序不可交换，每级有机械判据）

1. **oracle 拟合探针**（新，E 区装置）：每臂在**直接监督拟合 oracle** 时能否达到 oracle 水平。稠密控制若也能拟合 → 任务对该臂无分离 → **回第 0 步**。这一条正是 G1-BOUND 被审查判死的缺口（"架构级可达界"）。**v0.1 提升其地位**：C2 未证，故本闸是**唯一**能产生架构分离主张的关口；它失败即按 §7 关闭本配置，不得靠延长预算、换配置或换 `λ/σ/m/T` 救。
2. **余量门**：匹配控制的 oracle-relative KL 实测 `≥ δ`（δ 事前冻结，不假设）。
3. **学习门**：两臂均须过 IID 学习门（EXP-0013 死在门口，必须前置）。
4. **仅在前三级全过后**，才做效应比较，并附选择零与有效自由度披露（沿用本轮 `null_contrast` / `selection_null` 的做法）。
