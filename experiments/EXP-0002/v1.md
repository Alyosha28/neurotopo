# EXP-0002 v1 — Baseline learnability diagnostic

Registered after EXP-0001 v2 outcomes, before this diagnostic implementation/run. This is an exploratory infrastructure diagnosis, not a rescue comparison or a new claim about multi-trajectory effects.

Question: Can the same H64 dense GRU learn delayed-evidence-v1 with a longer fixed training budget, and does delay explain failure? Causal link: training budget / input delay → task computation. Prior-art context is unchanged (RIMs/TRNN/conn2res task boundaries).

Strongest rejection: eight-pair overfit from EXP-0001 proves finite-set memorization, not learning the generator. Longer training may resolve optimization while leaving semantic interpretation unchanged.

Frozen design: dense `gru_wide` only; 3 independent diagnostic seeds 71001–71003; training/evaluation delay conditions 0 and 8; 6,000 updates, batch64, Adam0.003, clip1, identical architecture and two-output loss. Fixed checkpoint measurements at updates400,2000,6000; no early stopping or checkpoint selection. Data seeds 300000+seed, held-out calibration seed400000+delay, 1,024 pairs. These are disjoint RNG streams from EXP-0001's test and train; generator/task distribution is shared. Evaluation at each checkpoint does not affect training.

At final update6000, declare the **bounded baseline-feasibility prediction** SUPPORTED only if every diagnostic seed at delay8 has pre accuracy≥0.90 and joint pair accuracy≥0.50. If this holds only at delay0, PARTIALLY_SUPPORTED for short-delay feasibility. Otherwise INCONCLUSIVE: optimization vs architecture/task difficulty remains unresolved. No FALSIFIED inference about multi-trajectory architectures is permitted here. Report all checkpoints/seeds, without best-checkpoint selection or causal explanation of why training failed.

No architectural stage gate may advance from this diagnostic. It informs a future newly registered comparison; EXP-0001 remains INCONCLUSIVE regardless of this result.

Run: `uv run --frozen python scripts/learnability.py --config configs/exp0002_v1.json`.
