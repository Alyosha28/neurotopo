# EXP-0010 v1 — 软更新门控温度的旧任务领域因素检验

2026-09-24，任何 EXP-0010 模型实现或训练结果前冻结。本协议接 FR-0001 零训练因素筛查、独立预决策批评和 packet-only 反思。轨道 `independent_benchmark`；它研究固定四值绑定/晚 selector 任务中的**温度驱动软更新 package**，不计 NeuroTopo Gate 1，也不称 RIMs 复现、竞争假设轨迹或独立新任务泛化。因旧 EXP-0004 结果曾启发这项设计，正式新种子只提供该已知任务族内的受限证据。

## 问题与最强反驳

在相同 H64/K2 分块 GRU、参数、状态、训练数据和完整执行更新路径下，更尖锐的互补软门控能否提高 OOD delay32 的 confirm/revise joint-pair accuracy？因果链仅是“更新门控温度 → 循环动力学/优化 → 已知检索任务表现”。最强反驳：`τ` 同时改变梯度与有效遗忘；门值分离不证明选择性**中介**性能，低温优势也可能只来自优化或长期模块偏置。四值缓存足以完成任务。此前 EXP-0004 的随机控制约67%不提供**新实际高温控制**的任何资格保证。

## 固定模型和数据

两臂同一个 `RecurrentModel` H64、K2 block mask、GRU、四类 readout，另有 `Linear(13,1)` 输入路由器。每 token 对两个32维模块都计算原 GRU `h_proposed`，`q=tanh(router(x_t))`，`g1=sigmoid(q/τ)`、`g2=1−g1`，`h_new^k=h_old^k+g_k(h_proposed^k−h_old^k)`。只改 `τ_low=0.2` 或 `τ_high=2.0`。两臂每配对种子同一初始化参数、mask、batch及顺序；均计算两个完整候选，不能据门控声称节省 GRU FLOPs。训练只用 `task.make_batch` 的 noise payload，delay0×2000、2×1000、4×1000、8×2000，共6000更新/臂/种子；Adam学习率0.003、batch64即32对、梯度裁剪1、CPU单线程、早晚交叉熵各0.5。无早停、预热权重、超参/任务菜单搜索或根据监控选检查点。

资格配对种子9601–9603，正式配对种子9801–9810，互不重合。训练流 RNG `760000+seed`，监控 RNG `790000+delay`，资格最终评估 RNG `770000+delay`，正式最终评估 RNG `780000+delay`；资格与正式每延迟各1024个成对 confirm/revise 样本。两臂在每个种子及阶段共用对应 batch；最终评估 delay8/32/64，32唯一主终点，8是学习护栏，64次级稳健性。监控400/2000/3000/4000/6000更新，256对，只记录不选择检查点。正式集在资格规则全部锁定、通过并封存后才训练/读取。每一步保留原始结果、模型、哈希与失败尝试；只此一个配置。总训练上限 `(3+10)×2×6000=156000` 更新，单项研究总墙钟上限3600秒；超时记录并停止，不挑有利完成种子。

## 实施与资源先验

预测每臂分配15,442参数、有效9,298参数、64递推 floats 和另外保留的4维 pre readout；实现后按张量逐项验证。相同算子/shape及全候选 GRU、router、sigmoid、门控混合路径是主执行配平；记录所有 dense linear MAC、router和逐元素算子计数、训练与推理实际耗时、峰值内存，注明分析 FLOP 不是完整硬件 FLOP。训练反传与优化器执行路径也必须同构；测得时延不强制完全相等，但差异必须报告，不可隐瞒或归功于稀疏执行。若参数/状态/路径不匹配，停止训练并标 `RESOURCE_MISMATCH`，不能用准确率作因果效果解释。

在任何**资格训练**前，完成 shape、零步确定性、配对初值/数据哈希、门范围、参数/缓存账、操作路径及小批 overfit 的工程验证；overfit 只测代码可学习性，不得查看资格/正式 final 流。这里的先后顺序是：冻结协议和独立预运行批评 → 实现与工程验证 → 资格种子训练/判定 → 若通过才训练正式种子。FR-0001 之前的“真正训练前”不表示资格指标无需训练。

## 资格门：只决定是否允许正式效应运行

每个资格种子两臂 delay8 的 pre accuracy≥0.90 且 joint-pair accuracy≥0.50；否则 `LEARNING_FAILURE`。**实际主控制**高温臂 OOD32 joint 的三种子均值须在[0.20,0.85]，并且每种子在[0.15,0.90]；否则 `CONTROL_FLOOR_OR_CEILING`。使用资格 OOD32 输入记录每 token `g1`，按 MEMORY、PRIOR、DISTRACTOR、EVIDENCE、QUERY 五事件分别报告样本数、mean(g1)、mean|g1−0.5|、二元门熵；先平均每种子输入位置/样本，避免较多干扰 token 淹没稀有事件。每个种子低温减高温的**五事件等权** mean|g1−0.5| 差须≥0.08，且 MEMORY 或 EVIDENCE 至少一个事件的差≥0.05；否则 `MANIPULATION_FAILURE`。门熵和事件间方向/变化是诊断，不能仅由门熵/固定块偏置推断有用选择。所有资格分支记录两臂实际数值；任一失败即关闭固定规格，不改τ、delay、阈值或任务后重试，也不启动正式训练。

## 正式效应和预写决定

正式十个**训练种子为独立配对单元**，同一固定1024-pair final 流只作为种子内评估。主差 `d_s=joint_low,s,32−joint_high,s,32`。用固定 RNG seed800001 对十个配对差做20,000次有放回种子 bootstrap，报均值、SD、95% percentile CI和所有种子。每个正式种子重复资格的 delay8 学习与五事件门值阈值作为解释护栏，报告高温 OOD32 余量；若任一正式种子学习/操纵失败或高温落出资格每种子[0.15,0.90]，主判 `INCONCLUSIVE`，保留性能和失败率。资源匹配失败同理。

若全部护栏通过，`SUPPORTED` 仅指已知任务族的温度软门控 package：主差均值≥+0.03、CI下界>0、且 delay32 confirm accuracy 的低温−高温种子均值≥−0.01。若前两项通过而 confirm 均值<-0.01，判 `PARTIALLY_SUPPORTED` 并明确权衡；若主差 CI上界<+0.03，判对预写≥3百分点**有用收益**的 `FALSIFIED`；其余 `INCONCLUSIVE`。若条件重叠，以学习/操纵/资源护栏先行，其次 `SUPPORTED`、`PARTIALLY_SUPPORTED`、`FALSIFIED`、`INCONCLUSIVE`。delay64、pre/revise/先验一致错误、每事件门值及训练曲线仅作次级报告，不移动主端点。即使正结果，也不得称选择性更新**中介**性能；该机制需另注册冻结权重门置平/交换与匹配扰动干预。

## 执行与审查

预运行独立批评必须审查资格/正式隔离、真实控制余量、数值操纵阈值与资源账；若审查要求改变协议，先升新版本并记录差异，绝不在读到 EXP-0010 模型表现后改 v1。正式运行由当前 `ResearchLoop` 的 QUESTION→PRIOR_ART→CRITIQUE→REGISTERED→VALIDATED→RUNNING→ANALYZED→REVIEWED→DECIDED 流程管理，随后仅 design/action packet 交独立上下文反思，主代理逐条核验并 react。旧 EXP-0004/0009 判词与 Gate 1 `NOT_PASSED` 原样保留。
