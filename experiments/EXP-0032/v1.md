# EXP0032 v1：修正端点上的控制菜单与预算扫描（A2 任务载体的最后一次校准）

2026-09-29。目的：决定 `DELAY-d` 任务族能否承载 A2 匹配对照。EXP0031 已证明 `w32/b1`、2000 更新下 d=2 的修正端点准确率只有 0.5991、d=3 0.6109，低于可学门槛 0.65；本轮把 A0 合同允许的**完整控制菜单**（`w∈{32,48,64,96}`×`blocks∈{1,2,3}`）以及更长预算试完，按运行前冻结的规则判定"是否存在既学得动又非封顶的条件"。不训练候选、不产生 A2 效果判词。

## 问题与最强反驳

在修正端点（`meaningful_accuracy`，只统计读出位置 `r∈[d+1,T]`）上，控制菜单内是否存在 `DELAY-d`（`d∈{2,3}`）条件满足：两 seed 均值 ≥0.65、每 seed ≥0.58（可学），均值 ≤0.95、每 seed ≤0.97（非封顶）？

最强反驳：EXP0031 观察到的是"短程部分策略"（前 1–2 个真实位置正确、之后回到随机），这既可能由容量不足造成（更大菜单能学会→可能直接到 1.0 封顶），也可能由任务本身在该接口下不可学（更大菜单仍是 ~0.6）。两种情形都关闭该任务族；只有落在带宽内才继续。菜单必须全部尝试并保留，不得据候选结果调整。

## 设计（运行前冻结）

- 任务、环境、评估流、参照集、oracle 与 EXP0031 完全一致（同一 `generate_memory`、`meaningful_accuracy`、四类无记忆参照、显式移位寄存器 oracle）。
- 控制：`INV_COMP`，配置取 A0 合同菜单的全集 `{(w,b): w∈{32,48,64,96}, b∈{1,2,3}}`（12 项）。监督固定为 `PLAIN`（仅实际序列损失）：EXP0031 中 `BRANCH` 在三个 `d` 上均未严格更高（d1 并列、d2 并列、d3 更低），且其末位标签构造缺陷已记录在案，故本轮不扫 `BRANCH`。
- Stage A（预算 2000，与 EXP0030/0031 相同课程与超参）：12 配置 × `d∈{2,3}` × seed `29101`，共 24 次拟合。
- 选择规则（冻结）：对每个 `d`，令 `S_d = {配置 : 0.65 ≤ meaningful(seed29101) ≤ 0.95}`。
  - 若 `S_2` 或 `S_3` 非空：按 `d=2 → d=3` 的顺序取第一个非空的 `d`；在该 `d` 的 `S_d` 中，按 A0 合同的匹配规则取 `|ln(控制推理算子量/候选推理算子量)|` 最小者（并列取参数少者）为选定配置，进入 Stage C。
  - 若 `S_2` 与 `S_3` 均为空：进入 Stage B。
- Stage B（仅当 Stage A 无合格者）：取 Stage A 中每 `d` 上 `meaningful` 最高的 3 个配置（两个 `d` 合并去重），改用预算 6000（课程 `[[1500,2],[3000,4],[4500,8],[6000,12]]`，其余超参不变）在 seed `29101` 上重跑，同样计算 `S_d`；仍按上面的规则选条件。
- Stage C（独立确认）：在选定 `(d, 配置)` 上跑 seed `29102`（第二扫描 seed）与 `29111,29112,29113`（独立确认 seed）。资格判据：5 个 seed 的 `meaningful` 均值 ≥0.65、每 seed ≥0.58、均值 ≤0.95、每 seed ≤0.97、无记忆参照 ≤0.55、oracle ≥0.99。
- 记录每个配置的参数、算子估计与实测时间；全部尝试与失败保留。

## 判词表（运行前冻结）

| 条件 | 判词 |
|---|---|
| 任一运行非有限/异常/缺记录 | `INCONCLUSIVE / ENGINEERING_FAILURE` |
| Stage A 与 Stage B 均无 `S_d` 非空 | `INCONCLUSIVE / CONTROL_MENU_EXHAUSTED_NO_BAND`（关闭该任务族） |
| 有候选条件但 Stage C 不满足资格判据 | `INCONCLUSIVE / QUALIFICATION_NOT_REPRODUCED` |
| Stage C 满足全部判据 | `SUPPORTED / A2_TASK_CARRIER_QUALIFIED`（限任务/预算/种子/配置） |

`SUPPORTED` 只表示该条件可以承载后续 A2 对照；它不是候选效果，也不改变 A1、A2、A3–A6 或旧 Gate 1 的既有状态。

## 附注（2026-09-29，v1 运行后的实现缺陷与 v2 重跑）

v1 运行后核查发现：`run_one` 只把 `width/blocks` 写进记录，没有注入传给 `fit_memory` 的配置，而该函数从 `cfg["control"]` 构造模型。因此 12 个"配置"实际训练的是同一个 `INV_COMP(w32,b1)` 模型——全部记录在同一 `(d, seed, budget)` 上共享同一个 `final_hash`、`meaningful` 完全相同，而记录里的参数量是账目值。v1 的全部产物保留为缺陷证据，其判词作废。

本协议的规则、菜单、带宽、选择规则与判词表**不作任何修改**；修正实现后以 `configs/exp0032_v2.json` 在 `artifacts/EXP-0032/v2/` 重跑同一套流程为权威结果。新增回归测试：注入后的控制配置必须到达模型（核对其参数量与 `param_count` 一致）。
