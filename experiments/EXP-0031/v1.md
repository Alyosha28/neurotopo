# EXP0031 v1：DELAY-d 任务资格的修正端点复核（同训练、修正评估与参照）

2026-09-29。本协议是 EXP0030 v1 的独立 packet 反思（`research/reflections/EXP-0030/`）触发的新版本复核。反思确认两项 high 问题：(1) EXP0030 的主端点 `accuracy_all` 把"越界取 0"的强制前缀位置计入整体准确率，无记忆策略可白拿这些位置；(2) 无记忆参照只测了"直通当前命令"，未测常数零、常数一与逐位置多数，而 d=2/T=12 的常数零期望准确率约 0.615，高于 0.55 的无记忆门槛。因此 EXP0030 的 `SUPPORTED / A2_TASK_QUALIFIED` 不足以支撑"控制可学且非封顶、无记忆解法无效"，须在修正端点下重新校准。

**本轮不改任务、不改训练**：任务生成、损失、课程、超参、控制臂、种子与 EXP0030 逐项相同，`src/neurotopo/arch0001_memory_task.py` 不修改；只增加修正端点的评估、扩充参照集、并核对重训模型与 EXP0030 归档哈希逐位一致（确定性复核）。凡哈希不一致即按工程失败处理并将该条件标为不可复核。

## 问题

在修正端点（只看目标非强制的读出位置）与扩充的无记忆参照下，`DELAY-d` 任务族是否仍存在使强控制 `INV_COMP(w32,b1)` 可学、非封顶、且无记忆策略无效的合格条件？

## 修正端点与参照（运行前冻结）

- 读出索引 `r=0..T`，目标 `y_r = u_{r−1−d}`（越界为 0，与 EXP0030 实现一致）。
- **主端点 `meaningful_accuracy`**：只在 `r ∈ [d+1, T]`（即目标为真实命令的位置）上统计准确率；同时报告逐位置准确率曲线、末位与后半段准确率，以及原 `accuracy_all` 供对照（不参与判词）。
- **无记忆参照集**（全部不训练，均在主端点位置上评估）：
  1. `constant_zero`：恒输出 0；
  2. `constant_one`：恒输出 1；
  3. `pass_through`：输出刚施加的当前命令 `u_{r−1}`；
  4. `position_majority`：用独立校准流（`root=[294001, 0, T, 0]`，4096 条）逐位置估计多数标签，再用于评估流。
  `memoryless_best` ＝在评估流上四项中的最大值。
- **oracle**：显式移位寄存器（输出 `u_{r−1−d}`），在主端点位置上恒为 1.0。

## 判词表（运行前冻结）

每个 `d`，两个监督变体（`PLAIN`、`BRANCH`）中主端点两 seed 均值较高者为该 `d` 的读数；均值差 ≤1e−9 视为并列，按 `PLAIN` 优先（显式写明的平局规则）。带宽：

- 可学：两 seed 均值 ≥ `max(0.65, memoryless_best_mean + 0.05)`，且每 seed ≥ `max(0.58, memoryless_best_max + 0.02)`；
- 非封顶：两 seed 均值 ≤0.95 且每 seed ≤0.97；
- oracle ≥0.99。

| 条件（互斥，按序判定） | 判词 |
|---|---|
| 任一模型哈希与 EXP0030 归档不一致、非有限、异常或缺记录 | `INCONCLUSIVE / ENGINEERING_OR_REPRODUCTION_FAILURE` |
| 无任何 `d` 满足全部带宽 | `INCONCLUSIVE / NO_QUALIFIED_MEMORY_CONDITION` |
| 首个合格 `d` 在独立确认 seed（29111–29113）上仍满足全部带宽 | `SUPPORTED / A2_TASK_QUALIFIED_CORRECTED` |
| 首个合格 `d` 在确认 seed 上不满足 | `INCONCLUSIVE / QUALIFICATION_NOT_REPRODUCED` |

`SUPPORTED` 只表示"在修正端点与扩充参照下，该任务条件对强控制可学、非封顶、无记忆策略无效、oracle 已知"，仍然**不是**候选效果、不是 A2 或 A1 通过。

## 已知记录缺陷与延后项

- EXP0030 配置里的任务描述字符串写成"readout index t>=1 equals u_{t-d}"，与协议/实现（`y_r = u_{r−1−d}`）相差一步；本轮以协议与实现为准，配置字符串缺陷记录在 `research/evidence/EXP-0031/provenance_check.json`，不追溯改写已冻结的 EXP0030 配置。
- 分支监督在末位索引复制 `y_T` 而非掩码（EXP0030 协议已注明）。合格变体为 `PLAIN`（不使用分支损失），故本轮不改；该缺陷连同 BRANCH 臂的独立确认留给候选 `v4` 合同一并修正并重跑。
- 重放脚本须分别暴露 `logits_hash_equal` 与 `branch_hash_equal`（EXP0030 记录只暴露了合并布尔值）。
- 运行前验收（pytest、`scripts/verify.py`、套件源码哈希与运行时一致）的通过记录、以及重放脚本哈希，均写入本轮 provenance 文件。
